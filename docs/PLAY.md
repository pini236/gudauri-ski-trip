## 2. רישום המזהים

**למה:** בקרוב טלפון אנדרואיד יתקין רק אפליקציות שהמזהה שלהן רשום למפתח מאומת. בישראל זה יחול ב-2027. גרסת החנות לא צריכה כלום מעבר ליצירה בקונסולה. **גרסת הבדיקה מ-GitHub צריכה רישום ידני,** אחרת יום אחד היא תפסיק להיות ניתנת להתקנה.

**הצעדים לגרסת הבדיקה** (בקונסולה, אחרי שהחשבון מאומת):
1. `Android developer verification`, הלשונית `Package names`, ואז `Register package name`.
2. שם החבילה ושם לזיהוי:
   ```
   io.github.pini236.skiapp.test
   Ski app (test build from GitHub)
   ```
3. `Add key`, ומדביקים את טביעת האצבע של מפתח הבדיקה:
   ```
   BA:09:08:B5:CB:5E:48:36:C7:78:70:B2:25:8E:5A:7B:43:13:45:34:81:4F:37:47:67:1D:6A:37:7C:E8:B3:06
   ```
4. הקונסולה נותנת **קטע טקסט קצר** (snippet). הוא לא סוד: הוא קושר את המזהה לחשבון, וההוכחה האמיתית היא החתימה במפתח. **שולחים אותו לסשן האפליקציה** (מותר להדביק בשיחה).
5. סשן האפליקציה מכניס אותו לקובץ בשם המדויק הזה, בתיקיית `assets` של גרסת הבדיקה בלבד:
   ```
   adi-registration.properties
   ```
   ובונה קובץ התקנה (`.apk`) **בגרסת שחרור** (`release`), חתום במפתח הבדיקה. בפרויקט, גרסת הבדיקה נקראת `preview`, ולכן הנתיב הוא:
   ```
   app/android/app/src/preview/assets/adi-registration.properties
   ```
6. מעלים את הקובץ הזה באותו דף בקונסולה. **הרישום הושלם.**

**גרסת החנות:** בודקים שהיא מופיעה באותה לשונית כרשומה. אם לא, אותו תהליך, עם מפתח ההעלאה.

## 3. מפתח ההעלאה

**מה זה:** בגרסת החנות גוגל שומרת את מפתח החתימה האמיתי (`Play App Signing`). אנחנו חותמים במפתח העלאה רק כדי להוכיח לגוגל שהקובץ מאיתנו. **אם הוא אובד או דולף, מבקשים מגוגל להחליף אותו,** והאפליקציה לא נפגעת. הקובץ הראשון שמועלה קובע אותו כמפתח ההעלאה.

**על המק, באותה דרך כמו מפתח הבדיקה:**
1. במנהל הסיסמאות: רשומה חדשה בשם `ski-app-upload`, עם סיסמה אקראית ארוכה (לפחות 24 תווים, אותיות ומספרים בלבד, כדי שלא תישבר בכלי הבנייה).
2. בטרמינל:
   ```
   mkdir -p ~/ski-app-keys && cd ~/ski-app-keys
   keytool -genkeypair -v -storetype PKCS12 -keystore ski-app-upload.jks -alias ski-app-upload -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=Pini Zolberg, C=IL"
   ```
   כשמתבקשת סיסמה, מדביקים את הסיסמה ממנהל הסיסמאות (פעמיים; היא לא תוצג). זו גם סיסמת המפתח. תוקף 10,000 ימים, כ-27 שנה, מעל מה שגוגל דורשת.
3. טביעת האצבע (**רק את השורה הזו שולחים ל-Claude**):
   ```
   keytool -list -v -keystore ski-app-upload.jks -alias ski-app-upload | grep SHA256
   ```
4. העתקת הקובץ ללוח, בשביל GitHub:
   ```
   base64 -i ski-app-upload.jks | pbcopy
   ```
5. ב-GitHub, בדף הריפו: `Settings`, ואז `Secrets and variables`, ואז `Actions`, ואז `New repository secret`. שלושה סודות, באותו סגנון כמו של מפתח הבדיקה:

   | שם הסוד | הערך |
   |---|---|
   | `ANDROID_UPLOAD_KEYSTORE_BASE64` | מה שבלוח (הדבקה) |
   | `ANDROID_UPLOAD_KEYSTORE_PASSWORD` | הסיסמה ממנהל הסיסמאות |
   | `ANDROID_UPLOAD_KEY_ALIAS` | `ski-app-upload` |

6. מצרפים את הקובץ `ski-app-upload.jks` לרשומה במנהל הסיסמאות.
7. מנקים: מעתיקים משהו אחר כדי לדרוס את הלוח, ומוחקים את התיקייה:
   ```
   cd ~ && rm -rf ~/ski-app-keys
   ```

**טביעת האצבע:** נרשמת ב-`docs/APP-NATIVE.md`, "לסשן של גוגל פליי".

5. **לפני כל העלאה:** רשימה קצרה של מה נוסף שנוגע לנתונים, כדי לעדכן את טופס הנתונים ואת המדיניות.

## 9. אחרי 14 הימים: הבקשה לפרסום

בדף הבית של הקונסולה: `Apply for production`. גוגל עונה בדרך כלל תוך שבעה ימים. השאלון בשלושה חלקים, וכדאי לאסוף את התשובות כבר במהלך הבדיקה:

1. **על הבדיקה:** כמה קל היה לגייס בודקים (חברים ומשפחה, דרך קבוצת גוגל), האם השתמשו בכל הפיצ'רים, האם השימוש דומה למה שיהיה בפרסום, ואיך נאסף משוב (וואטסאפ ומייל).
2. **על האפליקציה:** קהל היעד (גולשים שמגיעים לגודאורי, מגיל 13), מה הערך (מפה מדויקת בתלת-ממד, תצוגת מסלול, נקודת מפגש, עובד בלי קליטה), והערכת התקנות בשנה הראשונה.
3. **מוכנות:** מה שונה בעקבות המשוב, ואיך הוחלט שהאפליקציה מוכנה.

**אם גוגל דוחה:** בדרך כלל כי הבדיקה לא הייתה פעילה מספיק. ממשיכים עם הבודקים, מעלים עוד גרסה, ומגישים שוב.
