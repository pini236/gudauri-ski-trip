## מה מומש

| Emulator startup | מטמון AVD נקי לפני התקנת APK, בלי נתוני המשתמש/הבדיקה ומפתחות המארח. מפתח לפי גרסאות בפועל ותצורת המכונה. cache-hit אומת ב־GitHub; מדידת `home` אחת הייתה 334→338 שניות, ולכן אין הוכחת האצה של המשימה כולה. |
| Emulator timings | `timings.tsv` מפריד התקנה, תרחישים, בדיקות סיום וזמן כולל; שמות שגויים נכשלים לפני פעולת מכשיר. אין הרצה של כל התרחישים בגלל שגיאת כתיב. |
| Website CI | שני shards לכל מצב, בחירה ידנית של mode/file/title ותוצרים לפי shard. שמות בדיקות החובה נשמרו בשערים; אבחון אינו יכול להחליף ריצה מלאה. |
| Usage | `app_open.first_open` להתקנה טרייה שנפתחה, בלי ספירת שדרוגים מחדש; מדדי פתיחות, פעילים וחוזרים ושאילתות ב־[ANALYTICS.md](../../ANALYTICS.md). הורדות אמיתיות ב־Google Play Console. |
| Replay | מודול Sentry 8.59.0, הסכמה נפרדת כבויה כברירת מחדל, טקסט/תמונות ממוסכים. מסכי משחקים בלבד; מפה/מיקום, טיול, בית, חשבון וקבוצות אינם מוקלטים. אין שמירת הקלטה לשליחה מאוחרת; ביטול הסכמה מבטל תורים והרשאות מקטעים. PostHog ממשיך למדוד אירועים. |

## איך משתמשים

- באותה ריצה ו־SHA: **Re-run failed jobs**. GitHub מריץ מחדש גם את המשימות התלויות הדרושות; בנייה מוצלחת נשארת ואפשר להוריד את ה־APK כל עוד הוא נשמר. תיקון בקומיט חדש דורש בנייה חדשה; אין להשתמש ב־APK ישן.
- ב־`android-qa` אפשר לבחור `scenario=home` ו־`quick_debug=true` לאבחון. מצב זה אינו בודק את פתיחת גרסת release או בדיקת הדיווח הסופית; הוא מסומן כך בתוצאות. הרצה רגילה משאירה `quick_debug=false`.
- ב־`tests` ניתן לבחור מצב, קובץ וביטוי לשם בדיקה בהפעלה ידנית. בדיקות push/PR מריצות את כל ארבעת המצבים.
- ב־Sentry ההקלטות מגיעות רק אחרי הפצת גרסת האפליקציה החדשה והסכמת המשתמש בהגדרות. אין הקלטות רטרואקטיביות. נדרש מכשיר אמיתי לבדיקה חזותית; צילום משחקי OpenGL אינו מובטח בפיילוט, כי צילום SurfaceView כבוי.

## נתונים חיים

[לוח PostHog הקיים](https://eu.posthog.com/project/291066/dashboard/990610). לא נוספו גרפים לחשבון ולא נקראו ספירות חיות; אין מפתחות קריאה בסביבה. נשמרו דרישות `POSTHOG_READ_TOKEN` → `POSTHOG_PERSONAL_API_KEY` ל־`eu.posthog.com` ו־`SENTRY_READ_TOKEN` → `SENTRY_AUTH_TOKEN` ל־`de.sentry.io` בהגדרות הסביבה. נדרשות הרשאות קריאה בלבד, והזנת הערכים מאובטחת בהגדרות, לא בצ׳אט. שמירת הדרישות אינה מחברת חשבון או מפרסמת את הסביבה.

## אימות והמשך

בדיקות התהליך/תחביר, שימור הכיסוי, תרחישי הפרסום ובחירת התרחישים בוצעו. ב־main עברו בדיקות האתר המלאות ב־3:33; ריצת הבניות/חתימות/פרסומים העדכנית עברה ב־6:34, כולל פרסום בזמן ש־main התקדם בעדכון מסמכים. תיקון logcat אחרי החלפת שפה עבר בשחזור וב־GitHub: `phone` השלים את כל ארבע השפות בלי כשל. [ריצת האמולטור השנייה](https://github.com/pini236/gudauri-ski-trip/actions/runs/37606451675) ארכה 9:51, עם 14 חלקים שעברו וכשל `games`: גלילה מהבית לפני סיום הטעינה הגיעה לשלט מפגש. תוקנה המתנה למוכנות בפתיחה קרה, בלי שינוי UI או הסרת בדיקות. תוצאות האימות העדכניות ב־[STATUS.md](../../STATUS.md). אין כאן KVM ולכן לא בוצע אמולטור מקומי; תיקון המשחקים עדיין באימות. נדרשים גם בדיקת Replay חזותית במכשיר, אימות המכסה/זמן השמירה ב־Sentry והרצת שאילתות PostHog בחשבון.

מדידת מטמון באותו תרחיש `home`: [קרה](https://github.com/pini236/gudauri-ski-trip/actions/runs/37603080806/job/112733414264) מול [חמה](https://github.com/pini236/gudauri-ski-trip/actions/runs/37606451675/job/112743567122). יצירת snapshot ושמירתו דולגו בריצה החמה. הכנה ושחזור היו 106→71 שניות, אבל פעולת האמולטור והבדיקה הייתה 218→247 והורדת ה־APK התארכה; כל המשימה הייתה 334→338. זו תצפית אחת, ואין לייחס למטמון שיפור בזמן הכולל. פירוט `check-step` בדף הציבורי אינו מפריד אתחול פנימי מזמן התסריט.
