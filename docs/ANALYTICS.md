# כמה הורידו, פתחו והשתמשו באפליקציה

המדדים של האפליקציה מתחלקים בין החנות, שמכירה התקנות גם כשהאפליקציה לא נפתחה, לבין כלי המדידה, שרואה מה קרה אחרי הפתיחה. הקלטת מסך עוזרת להבין מקרה מסוים; הספירות ומשפכי השימוש אינם תלויים בה.

הלוח הקיים:

https://eu.posthog.com/project/291066/dashboard/990610

החוזה של האירועים נשאר ב־[GROWTH.md](GROWTH.md). המסמך הזה מגדיר את המדדים ואת השאילתות, בלי לשנות את שמות האירועים.

## מה כל מספר אומר

| השאלה | המקור והמדד | מה בדיוק נספר |
|---|---|---|
| כמה הורידו/התקינו מהחנות? | קונסולת גוגל פליי, נתוני רכישת משתמשים והתקנות | לבחור בין משתמשים חדשים, רכישות משתמשים ורכישות מכשירים; אלה מדדים שונים |
| כמה לחצו להורדה מהאתר? | אירוע לחיצה על הורדה | לחיצות וקוראים ייחודיים של האתר; זו אינה הוכחה להורדה או להתקנה |
| כמה פתחו? | אירוע פתיחת אפליקציה | מזהי התקנה אנונימיים ייחודיים; סכום האירועים הוא מספר הפתיחות, כולל חזרה מהרקע |
| כמה התקנות חדשות נפתחו? | אירוע פתיחה עם המאפיין לפתיחה ראשונה | התקנות טריות שנפתחו ונמדדו אחרי הכנסת המאפיין לגרסה; אין שחזור מדויק לגרסאות ישנות |
| כמה השתמשו ממש? | פעולת שימוש משמעותית, כמוגדר להלן | התקנות שעברו לפיצ'ר או ביצעו פעולה; פתיחה אוטומטית של דף הבית אינה מספיקה |
| כמה פעילים ביום, בשבוע ובחודש? | מזהים ייחודיים עם פעולת שימוש | חלונות נפרדים של 24 שעות, 7 ימים ו־30 ימים; אין לחבר ספירות יומיות כדי לקבל משתמשים חודשיים |
| כמה חוזרים? | פתיחות בשני ימים שונים לפחות בטווח הנבחר | התקנות שחזרו, כולל התקנות שנפתחו לראשונה באותו טווח |
| במה משתמשים? | מסכים, פתיחת מסלול, משחק, מפגש, שיתוף וקבוצה | מספר התקנות ייחודיות לכל יכולת ומספר הפעולות; אפשר לפלח לפי שפה וגרסה |
| כמה חוזרים אחרי יום/שבוע? | דוח שימור | קבוצה שנפתחה לראשונה בתקופה מסוימת, והחלק שחזר בתקופה הבאה |

**מזהה ייחודי אינו בהכרח אדם ייחודי.** אותו אדם בשני מכשירים נספר פעמיים; התקנה מחדש מחליפה את המזהה, והמזהים של האתר והאפליקציה אינם מקושרים. משתמש שכיבה את המדידה אינו מופיע בספירות. נתונים שנשלחו בלי קליטה יופיעו רק אחרי משלוח התור. אין צורך לחשוף חשבון, שם, מייל או מיקום כדי לקבל את המדדים האלה.

**דיוק ספירת הפתיחות:** מהגרסה שבה נכלל תיקון מחזור החיים, פתיחה קרה נספרת פעם אחת לכל תהליך של האפליקציה. חזרה מהרקע נספרת כפתיחה חמה; סיבוב המסך או שינוי שפה שמייצרים מחדש את המסך אינם פתיחה נוספת. שחזור מסך אחרי שמערכת ההפעלה סגרה את התהליך כן נספר כפתיחה קרה. בגרסאות קודמות יצירה מחדש של המסך יכלה להוסיף אירוע פתיחה, ולכן סכום הפתיחות ההיסטורי אינו תמיד מספר כניסות אמיתי. הספירה של מזהים ייחודיים אינה גדלה בגלל יצירה מחדש באותה התקנה.

### נתוני החנות

בקונסולת גוגל פליי בוחרים את האפליקציה, את דף הנתונים הסטטיסטיים ואת הטווח הרצוי. בקטגוריית המשתמשים בוחרים רכישת משתמשים ומשתמשים חדשים; בקטגוריית המכשירים רואים רכישת מכשירים והתקנות פעילות. יש להפריד התקנה ראשונה, התקנה מחדש, מכשיר נוסף והסרה לפי המדד שבוחרים. אפשר לשמור את הדוח ולייצא קובץ נתונים.

רכישות מדף החנות בדוח ההמרה מתארות את המשפך של **דף החנות**, ואינן תמיד מכסות את כל מקורות ההתקנה. נתוני החנות יכולים להתעדכן באיחור ולהיות מוגבלים כשיש מעט משתמשים. התקנות מקובץ מחוץ לחנות אינן נכללות בהורדות מגוגל פליי.

אי אפשר לחשב במדויק את מספר ההתקנות שלא נפתחו באמצעות חיסור מספרי החנות ממזהי כלי המדידה: אלה הגדרות שונות, ואין ביניהם קישור זהות.

### מסננים שחייבים להישאר

בלוח של האפליקציה בלבד מסננים לפלטפורמת אנדרואיד ולגרסת החנות; גרסאות בדיקה ואמולטורים אינם משתמשים. האמולטור מסומן גם במאפיין שהספרייה מוסיפה אוטומטית:

```text
platform = android
build = store
$is_emulator != true
```

רובוטי הבדיקות של גוגל אינם שולחים אירועי שימוש מהתיקון שהוכנס אחרי גרסה 0.1.68. לפני התיקון, חלקם רצו בטלפונים אמיתיים ואינם ניתנים להפרדה מהמשתמשים על סמך סימון אמולטור. ספירות היסטוריות הכוללות את הגרסאות הישנות יכולות עדיין לכלול אותם. אחרי התיקון, גם בגרסת החנות עדיין יש בודקים אנושיים מהבדיקה הסגורה; אלה משתמשים אמיתיים של מסלול הבדיקה.

לבדיקה נקייה של גרסאות שתוקנו אפשר להוסיף לסעיף הסינון בשאילתה את התנאי הבא. זו בחירה לדוח המסוים, ולא מסנן קבוע: **גם שימוש אמיתי בגרסאות הישנות יוצא מהתוצאה**. אין להציג תוצאה מסוננת זו כהיסטוריה מלאה מאז ההשקה.

```sql
AND NOT match(toString(properties.app_version),
    '^0[.]1[.]([0-9]|[1-5][0-9]|6[0-8])$')
```

## לוח מסכם שאפשר להריץ עכשיו

בפרויקט הקיים פותחים תובנה חדשה מסוג שאילתת נתונים, מריצים את השאילתה ושומרים ללוח הקיים. זה קישור לפרויקט, לא אישור שהשאילתות כבר נשמרו בו:

https://eu.posthog.com/project/291066

### פתיחות, שימוש וחזרה ב־30 יום

פעולת שימוש מוגדרת כאן כמעבר למפה, למפגש, למשחקים, לטיול או לקבוצה; או פעולה מפורשת כמו פתיחת מסלול, התחלת משחק, בחירת מפגש, שיתוף או יצירת קבוצה. הצגת מזג אוויר ומצב רכבלים אוטומטית בדף הבית אינה נחשבת כשלעצמה שימוש משמעותי.

```sql
WITH activity AS (
    SELECT
        distinct_id,
        event,
        timestamp,
        properties.first_open AS first_open,
        (
            (event = 'screen_view' AND properties.screen IN
                ('map', 'meet', 'games', 'game', 'trip', 'group'))
            OR event IN (
                'run_open', 'lift_open', 'run_fly_start',
                'run_profile_scrub', 'map_view', 'map_filter',
                'game_start', 'meet_pick', 'meet_share', 'run_share',
                'video_play', 'location_toggle', 'status_only_open',
                'group_create', 'group_join', 'meetup_create'
            )
        ) AS engaged
    FROM events
    WHERE timestamp >= now() - INTERVAL 30 DAY
      AND properties.platform = 'android'
      AND properties.build = 'store'
      AND ifNull(properties.$is_emulator, false) = false
), installs AS (
    SELECT
        distinct_id,
        countIf(event = 'app_open') AS opens,
        max(if(event = 'app_open' AND first_open = true, 1, 0)) AS new_install,
        uniqExactIf(toDate(toTimeZone(timestamp, 'Asia/Jerusalem')),
            event = 'app_open') AS open_days,
        max(if(engaged, 1, 0)) AS used,
        maxIf(timestamp, engaged) AS last_engaged
    FROM activity
    GROUP BY distinct_id
)
SELECT
    sum(opens) AS app_open_events,
    countIf(opens > 0) AS unique_opened_installations,
    countIf(new_install = 1) AS new_installations_opened,
    countIf(used = 1) AS unique_engaged_installations,
    countIf(open_days >= 2) AS installations_returned_on_another_day,
    countIf(used = 1 AND last_engaged >= now() - INTERVAL 1 DAY) AS engaged_last_24_hours,
    countIf(used = 1 AND last_engaged >= now() - INTERVAL 7 DAY) AS engaged_last_7_days,
    countIf(used = 1) AS engaged_last_30_days
FROM installs
```

עמודת ההתקנות החדשות מתמלאת רק אחרי פרסום גרסה עם המאפיין לפתיחה ראשונה. שדרוג של התקנה קיימת, פתיחה נוספת, חזרה מהרקע או הפעלת מדידה אחרי פתיחה קודמת אינם מסומנים כהתקנה חדשה. התקנה שעודכנה לפני שנפתחה בפעם הראשונה אינה נספרת כחדשה כאן; זו בחירה שמונעת ספירת שדרוגים כהתקנות חדשות. הסימון המקומי נשמר לדיסק לפני דיווח על התקנה חדשה; אם השמירה נכשלת, הפתיחה הזאת אינה מסומנת כחדשה. אין כתיבת זמן התקנה לאירוע, אלא מאפיין כן/לא בלבד.

### גרף פתיחות יומי

```sql
SELECT
    toDate(toTimeZone(timestamp, 'Asia/Jerusalem')) AS day,
    count() AS opens,
    uniqExact(distinct_id) AS unique_opened_installations,
    uniqExactIf(distinct_id, properties.first_open = true) AS new_installations_opened
FROM events
WHERE event = 'app_open'
  AND timestamp >= now() - INTERVAL 30 DAY
  AND properties.platform = 'android'
  AND properties.build = 'store'
  AND ifNull(properties.$is_emulator, false) = false
GROUP BY day
ORDER BY day
```

יום קלנדרי מוצג בשעון ישראל; הוא אינו זהה לחלון של 24 שעות בשאילתה הקודמת. גם ימים בודדים עם משתמש יחיד יכולים להופיע, בלי לתת לזהות את האדם.

### במה השתמשו

```sql
SELECT
    event,
    if(event = 'screen_view', toString(properties.screen),
        if(event = 'game_start', toString(properties.game), '')) AS feature,
    uniqExact(distinct_id) AS installations,
    count() AS actions
FROM events
WHERE timestamp >= now() - INTERVAL 30 DAY
  AND properties.platform = 'android'
  AND properties.build = 'store'
  AND ifNull(properties.$is_emulator, false) = false
  AND (
      (event = 'screen_view' AND properties.screen IN
          ('map', 'meet', 'games', 'game', 'trip', 'group'))
      OR event IN ('run_open', 'lift_open', 'run_fly_start', 'game_start',
          'meet_pick', 'meet_share', 'run_share', 'video_play',
          'group_create', 'group_join', 'meetup_create')
  )
GROUP BY event, feature
ORDER BY installations DESC
```

מספרי ההתקנות לכל פיצ'ר חופפים; אדם יכול לפתוח גם מפה וגם משחק, ולכן אין לסכום אותם כדי לקבל משתמשים כלליים. במשחקים סיום והצלחה נמדדים באירוע סיום המשחק, עם משך ותוצאת השלמה, כפי שכבר מופיע בלוח הקיים.

### משפכים ושימור

משפך שימוש ראשון: פתיחת אפליקציה עם המאפיין לפתיחה ראשונה, אחריה מעבר למסך המפה ואחריו פתיחת מסלול. מגדירים חלון המרה של יום, ספירת מזהים ייחודיים ואת מסנני החנות. משחקים: פתיחה, התחלת משחק וסיום המשחק; אפשר לסנן את הסיום להשלמה. המשפך הוא מדד לפי התקנה, לא מעקב אחרי אדם מזוהה.

בדוח שימור מגדירים אירוע התחלה לפתיחה ראשונה ואירוע חזרה לפתיחת אפליקציה, ובוחרים ימים או שבועות. שימור של גרסאות ישנות אפשר לחשב לפי הפתיחה **הראשונה שנצפתה** בנתונים, אך היא אינה בהכרח פתיחה אחרי התקנה. אין לקרוא לאותה קבוצה "התקנות חדשות". יש להמתין לסיום חלון החזרה לפני שמסיקים מסקנה על השימור; יום ראשון של התקנה חדשה אינו כישלון של שימור בשבוע הבא.

## מה אומת ומה מחייב גישה חיה

נבדקו חוזה האירועים, קריאות המדידה באפליקציה, מזהה הפרויקט וקישור הלוח מהתיעוד. המאפיין של פתיחה ראשונה נוסף לקוד, עם בדיקות לשדרוג, פתיחה חוזרת ומעבר מגרסאות ישנות. שאילתות המסמך הוכנו לפי סכמת האירועים הקיימת; הן לא הורצו מול הפרויקט החי בסשן הזה. לא נקראו נתוני גוגל פליי ולא נשמרו גרפים חדשים בפרויקט.

מפתח משלוח האירועים שבאפליקציה אינו הרשאת קריאה לנתוני הפרויקט. כשאין חיבור מורשה לכלי המדידה או לקונסולת החנות, אין מספר משתמשים חי שאפשר לדווח עליו בביטחון. אין לשלוח סיסמה או מפתח ניהול בצ'אט; חיבור והרשאות ניתנים דרך הגדרות השירות או הסביבה.
