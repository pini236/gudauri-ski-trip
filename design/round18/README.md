# סבב 18: יישור קו בין האתר לאפליקציה (הושהה, 4.10.2026)

**מה זה:** סבב קנבס לפריטים ב-`docs/PARITY.md` שמחכים לאישור של פיני לפני קוד: K-2 עד K-5, P-K2, A-28, המתג ביצירת קבוצה (החלק שנשאר מ-S-1), ופערי המראה שנשארו מסבב 16. לבקשת סשן המנהל (4.10.2026, לפי החלטה 50).

**למה הושהה:** החלטה 54 (צוות רזה מאוד): סשני הקנבס רדומים. כאן כל מה שנאסף עד ההשהיה, כדי שמי שימשיך לא יתחיל מאפס. **עוד לא נבנה אף לוח בקנבס, ושום דבר לא שונה באתר ובאפליקציה.**

## איך ממשיכים

1. צילומי האתר של היום: `shots.mjs` (על הסביבה של סבב 16, עם שרת מדומה ושמות מומצאים). הוא מצלם את דף הקבוצה (טיסות, מפגשים, חברים, מילוי טיסה לחבר, יצירת קבוצה), החשבון עם שתי קבוצות, טופס הטיול, כותרת דף הבית בשלושת המצבים, המפה באנגלית, ורכיבים חתוכים ביום ובלילה (שלטים, מתג, לשוניות, כרטיס ההזמנה, הכרטיס הריק).
2. צילומי האפליקציה: מהבדיקה באמולטור, בגרסה `android-qa` של GitHub (קובץ `qa.zip`, תיקייה `shots`). הרלוונטיים: `group-17` (טיסות), `group-20` ו-`group-29` (מפגשים, מחיקה בשתי נגיעות), `group-26` (מילוי טיסה לחבר), `group-03` (קבוצה חדשה עם המתג), `group-31` (חשבון), `group-06` (הזמנה), `group-32` (קבוצה בלילה), `home-07` (בחירת שדה תעופה), `home-10` ו-`home-22` (כותרת דף הבית), `home-28` (אודות), `run-15` ו-`meet-14` (באנגלית).
3. לכל פריט לוח אחד: באתר היום, באפליקציה היום, וההצעה. הצעה לאתר מצוירת בתוך האתר האמיתי בזמן הצילום (כמו בסבבים 12 ו-16); הצעה לאפליקציה מורכבת מהמסכים שלה. עמוד "סבב 18" בקנבס המשותף, עם כרטיס "מה לאשר".
4. פערי המראה: ברירת המחדל היא שהאפליקציה מתיישרת לאתר של היום, עם הערה בולטת שאם פיני יבחר שפה עיצובית חדשה, היא מחליפה את שניהם. סשן השפה העיצובית הסכים, והפנה ללוחות שלו בקנבס https://claude.ai/artifact/9yxrGgytb2Gmi4i1UqEhST : `<L>1-Core` (מתג, לשוניות, כפתורים), `<L>2-Domain` (הזמנה, שורת טיסה בקבוצה, "ההר עוד ישן"), `<L>4-HomeNight`, `<L>9-Group`, `<L>10-Settings` (`<L>` היא האות של השפה, A עד E).
