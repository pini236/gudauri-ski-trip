# השרת: Supabase

השרת של שלב 13.5: חשבונות, קבוצות, הזמנות, טיסות, מפגשים ושיאים. המפרט ב-`docs/USERS.md`, וההחלטות ב-`docs/STATUS.md` (26 עד 28, 34).

**מצב (1.10.2026): מוכן ובדוק, ועוד לא נוצר פרויקט.** הפרויקט נוצר רק באישור של פיני (החלטה 28). עד אז הכל מקומי: מיגרציות, הרשאות, פונקציות ובדיקות.

## מה יש כאן

| קובץ | מה בו |
|---|---|
| `supabase/config.toml` | ההגדרות של הפרויקט המקומי: אורח (זהות אנונימית), גוגל ואפל, בלי מייל, וכמה דרכי התחברות לחשבון אחד. הסודות רק ממשתני סביבה |
| `supabase/migrations/` | מבנה הנתונים וההרשאות (`*_schema.sql`), הפעולות (`*_functions.sql`) והמשימה היומית (`*_keepalive.sql`) |
| `supabase/tests/` | בדיקות ההרשאות (pgTAP): 163 בדיקות בשבעה קבצים |
| `test.sh` | מריץ את הבדיקות. כל קובץ בטרנזקציה משלו, שמבוטלת בסוף |
| `tests/helpers.sql` | עזרים לבדיקות: יצירת משתמש או אורח, ופעולה בשם משתמש |
| `tests/shim/supabase.sql` | תחליף מינימלי למה שיש בסופבייס (התפקידים, `auth.users`, `auth.uid()`), כדי להריץ על פוסטגרס רגיל בלי דוקר |

## הבדיקות

ב-GitHub הן רצות אוטומטית בכל שינוי בתיקייה (`.github/workflows/server.yml`), פעמיים: על מסד הנתונים האמיתי של סופבייס, ועל פוסטגרס רגיל.

מקומית, על פוסטגרס 16 עם pgTAP (בסביבת הענן אין דוקר):

```
DB_URL=postgresql://postgres:postgres@127.0.0.1:5432/postgres server/test.sh --fresh
```

עם סופבייס מקומי (דורש דוקר):

```
cd server && supabase db start
server/test.sh
```

**מה נבדק:** אבטחת שורות בכל טבלה; מי שלא מחובר לא רואה כלום; מי שמחוץ לקבוצה לא רואה קבוצה, חברים, הזמנות, טיסות, מפגשים ושיאים; חבר לא מבצע פעולות ניהול; מנהל חייב להיות רשום; תמיד נשאר מנהל כשאפשר; קבוצה מתוקף, ביטול, הגבלת שימושים ואישור ידני של הזמנה; **ניחוש קוד** (חסימה אחרי 5 טעויות ברבע שעה, 20 ביום, ובלם כללי של 300 בשעה רק לקודים הקצרים); כל קבוצה רואה רק את הטיסה שהחבר בחר לה; "אני על אותה טיסה"; מנהל שממלא טיסה, עד שהחבר משנה; "אני כבר בקבוצה"; אורח שהופך לחשבון קיים; מחיקת חשבון מלאה; המשימה היומית.

## מבנה הנתונים

| טבלה | מה | מי רואה | מי משנה |
|---|---|---|---|
| `profiles` | שם, שפה | רק אני | אני (שם ושפה) |
| `trips` | הטיול: טיסות הלוך וחזור (כמו `site/data/trip.json`), ימי סקי, "מי הזין" | אני, וכל קבוצה רק את הטיול שבחרתי לה | אני; מנהל רק דרך `set_member_trip` |
| `groups` | שם ותאריכים | חברי הקבוצה | רק דרך הפונקציות |
| `group_members` | תפקיד, שם בקבוצה, הטיול שמוצג | חברי הקבוצה | רק דרך הפונקציות |
| `invites` | קוד של שש אותיות, אסימון לקישור, תוקף, שימושים, אישור ידני | חברי הקבוצה (כולם משתפים) | מנהל, דרך הפונקציות |
| `join_requests` | בקשות שממתינות לאישור, ו"אני כבר בקבוצה" | המבקש ומנהלי הקבוצה | דרך הפונקציות |
| `meetups` | תחנה (מזהה מנתוני המפה), שעה, הערה | חברי הקבוצה | כל חבר |
| `scores` | השיא שלי בכל משחק | אני ומי שאיתי בקבוצה | רק דרך `submit_score` |

בסכמה `private` (לא חשופה ל-API): ניסיונות קוד, כרטיסי מיזוג, והמונה של המשימה היומית.

**מגבלות נגד ניצול** (`private.limits()`, ניחוש ראשון): 20 טיולים לאדם, 20 קבוצות שאדם יוצר, 100 חברים בקבוצה, 300 מפגשים בקבוצה. אורח שאינו בשום קבוצה נמחק אחרי 30 יום.

## מה כל אפליקציה צריכה מהשרת

**התחברות** (ספריית סופבייס: רשמית לאייפון ולאתר, של הקהילה לאנדרואיד):
- אורח: לא נוגעים בשרת בכלל. רק כשמצטרפים לקבוצה: `signInAnonymously()`, ואז `join_group`.
- גוגל (אנדרואיד, אייפון, אתר) ואפל (אייפון, אתר): `signInWithIdToken` מהחלון של המערכת.
- **אורח שנרשם:** `linkIdentity` (או אסימון מגוגל או אפל) הופך את אותה זהות לחשבון, וכל הנתונים נשארים. **אם החשבון כבר קיים:** כאורח `create_merge_ticket()`, אחרי ההתחברות `merge_guest(ticket)`.

**הפעולות** (`rpc`). שגיאה מחזירה קוד קצר (למשל `not_admin`), והאפליקציה מתרגמת לשפה שלה. פעולות ההצטרפות מחזירות `{"status": ...}` במקום שגיאה.

| פעולה | מי |
|---|---|
| `my_account()`, `delete_my_account()` | כל מחובר |
| `create_merge_ticket()`, `merge_guest(ticket)` | אורח, ואחר כך החשבון |
| `create_group(name, display_name, starts_on, ends_on, trip_id)` | רשום |
| `invite_preview(code)`, `join_group(code, display_name)`, `request_reclaim(code, member)` | כל מחובר. הקוד הוא שש האותיות או האסימון מהקישור |
| `cancel_join_request(id)` | המבקש |
| `set_my_membership(group, display_name, trip_id)`, `same_flight(group, trip)`, `leave_group(group)` | חבר |
| `update_group`, `delete_group`, `create_invite`, `revoke_invite`, `decide_join_request`, `remove_member`, `set_member_role`, `set_member_trip` | מנהל |
| `claim_admin(group)` | חבר רשום, בקבוצה שנשארה בלי מנהל |
| `submit_score(game, score)`, `group_leaderboard(group, game)` | כל מחובר; הטבלה לחברים |
| `keepalive()` | כולם (המשימה היומית) |

**קריאה ישירה מהטבלאות** (`select`), והרשאות השורה מסננות. כתיבה ישירה רק ל-`trips`, `meetups` ול-`profiles` (שם ושפה).

**זמן אמת:** האפליקציה מאזינה לשינויים ב-`groups`, `group_members`, `trips`, `invites`, `join_requests`, `meetups`, `scores`. השרת מסנן לפי אותן הרשאות.

**בלי קליטה:** כל אפליקציה שומרת עותק מקומי של הקבוצות, החברים, הטיסות, המפגשים והשיאים, ותור של שינויים (מפגשים, טיול, שיא) שנשלח כשחוזרת הקליטה. `submit_score` שומר רק שיא גבוה יותר, ולכן שליחה כפולה לא מזיקה. מפגשים: האחרון שנשמר גובר. התזכורת למפגש מתוזמנת בטלפון.

**גרסאות ישנות:** כל שינוי בשרת חייב לא לשבור אפליקציה ישנה (`docs/APP-NATIVE.md`): מוסיפים עמודות ופונקציות, לא משנים ולא מוחקים.

## מה פיני מגדיר כשיוצרים את הפרויקט

אף סוד לא נכנס לריפו. הסדר:

1. **יצירת פרויקט** בתוכנית החינמית, באזור באירופה (פרנקפורט). בארגון `ski-app` (נפתח לזה, כי בחשבון החינמי מותרים שני פרויקטים פעילים). Claude יוצר אותו דרך החיבור לסופבייס, אחרי שהארגון נוסף לחיבור.
2. **מיגרציות:** `supabase link` ואז `supabase db push` מתוך `server/` (או Claude דרך החיבור לסופבייס, באישור).
3. **Authentication > Sign In / Providers:**
   - **Anonymous sign-ins:** להדליק.
   - **Allow manual linking:** להדליק.
   - **Email:** לכבות הרשמה במייל.
   - **Google:** מזהי לקוח מ-Google Cloud Console: לקוח אינטרנט (עם הסוד), ולקוח אנדרואיד לכל מזהה (`io.github.pini236.skiapp` ו-`.test`) עם טביעת האצבע של מפתח החתימה (של גוגל פליי למפתח החנות, ושל מפתח הבדיקה). בשדה מזהי הלקוח: כל המזהים, מופרדים בפסיקים.
   - **Apple:** מזהה שירות ומפתח מ-Apple Developer (כשחשבון אפל קיים). **המפתח הסודי של אפל לאתר פג כל חצי שנה** וצריך לחדש אותו.
4. **Authentication > Rate Limits:** כניסות אנונימיות לשעה לכל כתובת (ברירת מחדל 30; להשאיר). **CAPTCHA:** לשקול רק אם יהיה ניצול, כי באפליקציה נייטיב זה מסורבל.
5. **Authentication > URL Configuration:** כתובת האתר וכתובות החזרה של האפליקציות (כמו ב-`config.toml`).
6. **GitHub > Settings > Variables:** `SUPABASE_URL` ו-`SUPABASE_PUBLISHABLE_KEY` (המפתח הציבורי), כדי שהמשימה היומית תתחיל לעבוד (`.github/workflows/server-keepalive.yml`). להריץ אותה פעם אחת ידנית ולוודא שעברה.

## המשימה היומית

בתוכנית החינמית, פרויקט בלי מספיק פעילות שבוע מושהה (החלטה 28). `server-keepalive.yml` רץ ב-GitHub פעם ביום וקורא ל-`keepalive()` דרך ה-API הציבורי. הפונקציה מעדכנת מונה, ופעם ביום גם מנקה אורחים שאינם בשום קבוצה (30 יום) וניסיונות קוד ישנים. GitHub מכבה משימות מתוזמנות בריפו בלי פעילות 60 יום, ושולח מייל לפני.
